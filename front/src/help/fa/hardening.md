# اجرای مقاوم‌سازی

تنظیمات امن را **روی دستگاه اعمال می‌کند**، با پیش‌نمایش دستورها، پشتیبان پیش از تغییر و راستی‌آزمایی پس از آن. فقط با مجوز تغییر سازمان (مثلاً درخواست تغییر تأییدشده) اجرا کنید.

## دو راه

| گزینه | کی |
|---|---|
| اصلاح همهٔ بخش‌ها | دارایی‌ای که هنوز ممیزی نشده: اول ممیزی، سپس مقاوم‌سازی همهٔ بخش‌های بنچمارک CIS |
| اصلاح بخش‌های ناموفق | دارایی‌ای که ممیزی شده: کنترل‌های ناموفق همان ممیزی (روش معمول) |

## گام‌ها (اصلاح بخش‌های ناموفق)

1. «اصلاح بخش‌های ناموفق» ← «بعدی» ← نشست ممیزی دارایی.
2. **بازبینی:** کنترل‌هایی را که باید اصلاح شوند علامت بزنید. مواردی که اصلاح خودکار ندارند (مثلاً تنظیمات فقط از راه GPO) کنار گذاشته می‌شوند.
3. **پارامترها:** برای کنترل‌های «نیاز به پارامتر» مقدار بدهید (طول رمز، نشانی سرور Syslog و …). فیلد اختیاری خالی یعنی پیش‌فرض CIS.
4. **اطلاعات ورود:** فقط برای همین اجرا به کار می‌رود و ذخیره نمی‌شود.
5. **«ابتدا از پیکربندی دستگاه پشتیبان بگیر»** را روشن نگه دارید.
6. **«پیش‌نمایش دستورها»:** دستورهای دقیق بدون اتصال و بدون تغییر. آن‌ها را بخوانید.
7. **«اعمال مقاوم‌سازی»**.

## نتیجه

| نتیجه | معنی |
|---|---|
| اصلاح‌شده | دستورها بی‌خطا اجرا شدند **و** راستی‌آزمایی تغییر را تأیید کرد |
| ناموفق | دستور خطا داد یا راستی‌آزمایی تغییر را ندید؛ خروجی را بخوانید |
| ردشده | قابل اصلاح خودکار نبود یا انتخاب نشد |

پس از مقاوم‌سازی، دارایی را **دوباره ممیزی کنید**.

## مثال

`fw-edge`، کنترل قفل حساب مدیر پس از ورود ناموفق. پارامترها: آستانه `3` و مدت `60` ثانیه. پیش‌نمایش:

```
config system global
 set admin-lockout-threshold 3
 set admin-lockout-duration 60
end
```

## مراقب باشید

> برخی تنظیمات (محدود کردن SSH، سیاست‌های ورود) ممکن است دسترسی شما یا NGCorion را قطع کنند. پیش‌نمایش را با این دید بخوانید و راه دسترسی جایگزین (کنسول) داشته باشید. برای تجهیزات حیاتی کنترل‌ها را تک‌تک یا در گروه‌های کوچک اجرا کنید، نه «مقاوم‌سازی همهٔ بررسی‌های ناموفق». برای ESXi سرویس SSH باید در طول کار روشن باشد.

## خطاهای رایج

| وضعیت | راه |
|---|---|
| همه «ناموفق» | اطلاعات ورود یا دسترسی sudo/Enable را بررسی کنید |
| پس از اصلاح دسترسی SSH قطع شد | از کنسول وارد شوید؛ اگر پشتیبان گرفته‌اید از [پشتیبان دستگاه‌ها](/backup) بازیابی کنید |
| ممیزی بعدی هنوز ناموفق نشان می‌دهد | خروجی دستورها؛ برخی تغییرها راه‌اندازی دوبارهٔ سرویس می‌خواهند |
