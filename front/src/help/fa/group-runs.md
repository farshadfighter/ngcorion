# ممیزی‌های گروهی

همهٔ دارایی‌های یک گروه را در یک کار ممیزی می‌کند، با یک **پروفایل اعتبارنامه** که مدیر سیستم ساخته است (شما رمز آن را نمی‌بینید). هر دارایی ممیزی معمولی خودش را می‌گیرد؛ دارایی‌هایی که ممیزی نشدند با دلیل فهرست می‌شوند و می‌توان دوباره امتحانشان کرد.

## شروع یک ممیزی گروهی

1. «شروع ممیزی گروهی».
2. **گروه دارایی**، **فناوری** و **سطح بنچمارک** («سطح ۱» یا «کامل (سطح ۱ و ۲)»).
3. **پروفایل اعتبارنامه** از همان نوع (SSH، WinRM، SQL Server یا API سوفوس).
4. **تعداد دارایی‌هایی که هم‌زمان ممیزی می‌شوند:** ۱ تا ۵۰.
5. «شروع».

## خواندن نتیجه

ردیف هر اجرا پیشرفت را نشان می‌دهد؛ با باز کردنش، نتیجهٔ هر دارایی:

| نتیجه | معنی و راه |
|---|---|
| ممیزی شد | از ستون «انطباق» به جلسهٔ آن بروید |
| ورود رد شد | حساب یا رمز sudo روی این دستگاه نیست یا فرق دارد |
| خارج از دسترس | فایروال، دستگاه خاموش یا پورت دیگر |
| کنار گذاشته (مجوز یا نبود نشانی) | بیرون از سقف لایسنس، یا دارایی بدون IP |
| خطا | جزئیات را بخوانید |

- **«تلاش دوباره برای n مورد ناموفق»:** فقط همان‌ها را دوباره ممیزی می‌کند.
- **«توقف»:** دارایی‌هایی را که شروع نشده‌اند لغو می‌کند؛ ممیزی‌های در حال اجرا تمام می‌شوند.
- اگر در پایان دارایی ناموفقی باشد، هشدار «ممیزی گروهی با خطا پایان یافت» صادر می‌شود.

## مثال

گروه «سرورهای لینوکس»، فناوری Linux، سطح ۱، پروفایل `linux-audit`، ۱۰ هم‌زمان. دو سرور «ورود رد شد» می‌شوند چون حساب `ngc-audit` روی آن‌ها ساخته نشده است؛ پس از ساخت حساب، «تلاش دوباره برای ۲ مورد ناموفق».

## چه کسی می‌تواند؟

مجوز نوشتن «ممیزی» به‌علاوهٔ مجوز «استفاده از پروفایل‌های اعتبارنامه». اگر پروفایلی از نوع لازم نیست، از مدیر سیستم بخواهید بسازد. اگر رمز پروفایل از دورهٔ تعویضش قدیمی‌تر باشد، کنارش هشدار می‌آید.
