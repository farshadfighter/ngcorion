# میزبان‌ها

همهٔ دارایی‌ها با وضعیت پایش SNMP، مصرف پردازنده، حافظه و دیسک و زمان آخرین پایش. با کلیک روی هر دارایی، صفحهٔ میزبان: اطلاعات سیستم، سلامت دستگاه، اینترفیس‌ها، تاریخچه و اطلاعات ورود SNMP.

## شروع پایش یک دستگاه

1. **روی دستگاه:** کاربر SNMP فقط‌خواندنی بسازید. نمونهٔ Cisco با SNMP v3:

    ```
    snmp-server group NGC-RO v3 priv
    snmp-server user ngc-mon NGC-RO v3 auth sha <رمز-Auth> priv aes 128 <رمز-Priv>
    ```

2. **در NGCorion:** صفحهٔ میزبان ← «اطلاعات ورود SNMP»: نسخه v3، نام کاربری `ngc-mon`، «پروتکل Auth» SHA، «پروتکل Priv» AES و کلیدها ← «ذخیره».
3. «پایش اکنون».

اطلاعات ورود SNMP رمزنگاری‌شده ذخیره می‌شود. v3 با Auth و Priv را بر v2c (community) ترجیح دهید.

## صفحهٔ میزبان

| بخش | چه چیزی |
|---|---|
| اطلاعات سیستم | نام، سیستم‌عامل/میان‌افزار، مکان و مسئول که خود دستگاه گزارش می‌دهد |
| سلامت دستگاه | پردازنده، حافظه، پرترین فایل‌سیستم، داغ‌ترین حسگر دما و مدت روشن بودن |
| اینترفیس‌ها | وضعیت، سرعت و ترافیک ورودی/خروجی هر پورت |
| تاریخچه | نمودار دسترس‌پذیری، ترافیک و سلامت در هر بازه |

اگر دستگاه پاسخ ندهد، آخرین مقادیر گزارش‌شده با یادداشت می‌ماند. راه‌اندازی دوبارهٔ دستگاه تشخیص داده می‌شود و هشدار «دستگاه راه‌اندازی مجدد شد» می‌دهد.

## هشدارهای سلامت

«مصرف پردازنده بالاست» و «مصرف حافظه بالاست» (همهٔ پایش‌های یک بازه در ۹۰٪ یا بیشتر)، «دیسک تقریباً پر است» (۹۰٪) و «دما بالاست» (۷۰ درجه). آستانه‌ها در [قواعد هشدار و اعلان](/settings/notifications) تغییر می‌کنند.

## خطاهای رایج

| وضعیت | علت |
|---|---|
| «خارج از دسترس» با اطلاعات ورود درست | فایروال UDP 161 را از NGCorion نمی‌پذیرد |
| اطلاعات سیستم خالی است | دستگاه گروه system در MIB-2 را از راه SNMP نمی‌دهد |
| سلامت لینوکس خالی است | view پیش‌فرض net-snmp بسته است؛ HOST-RESOURCES و UCD را اضافه کنید |
| دما خالی است | ماشین مجازی حسگر دما ندارد |
