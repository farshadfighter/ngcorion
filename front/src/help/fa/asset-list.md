# فهرست دارایی‌ها

همهٔ سرورها، تجهیزات شبکه، پایگاه‌های داده و سرویس‌هایی که NGCorion می‌شناسد. هر بخش دیگر نرم‌افزار بر پایهٔ این فهرست کار می‌کند: ممیزی و پشتیبان‌گیری روی دارایی اجرا می‌شوند، Syslog فقط از نشانی دارایی‌ها پذیرفته می‌شود و ریسک از ناحیه و اهمیت دارایی حساب می‌شود.

## کارهای اصلی

1. **افزودن یک دارایی:** «افزودن دارایی» ← نام، نام میزبان، نشانی IP، نوع، سیستم‌عامل، مکان، مالک، ناحیه و سطح اهمیت. اگر نشانی IP را دارایی دیگری هم داشته باشد، ثبت می‌شود ولی هشداری نام آن دارایی را می‌آورد: پیام‌های syslog و دستگاه‌هایی که از نشانیِ مشترک دیده می‌شوند فقط به یکی از آن‌ها نسبت داده می‌شوند.
   فقط نام و نوع الزامی‌اند؛ بقیه (شماره سریال، ارزش و …) را بعداً هم می‌توان افزود. تاریخ آخرین ممیزی و آخرین مقاوم‌سازی خودکار پر می‌شوند: وقتی ممیزی دارایی تمام شود و وقتی یک تغییر مقاوم‌سازی روی آن موفق شود.
2. **افزودن گروهی:** «دریافت الگو» ← فایل Excel را پر کنید ← «⬇ درون‌ریزی». ردیف‌های نادرست با دلیل گزارش می‌شوند.
3. **تغییر گروهی:** کادر کنار چند ردیف را بزنید؛ نوار بالای جدول برچسب، مالک، مکان، وضعیت، ناحیه و گروه را یک‌جا تغییر می‌دهد.
4. **دیدن همه‌چیز دربارهٔ یک دارایی:** روی نام آن بزنید (ریسک، ممیزی‌ها، آسیب‌پذیری‌ها، پشتیبان‌ها، پایش و خط زمانی).

## مثال

| فیلد | مقدار |
|---|---|
| نام | `pay-app` |
| نشانی IP | `10.20.5.10` |
| نوع | سرور · Ubuntu 22.04 |
| ناحیه | محیط کارت |
| اهمیت | بالا |
| میزبان | `esx-01` (ماشین مجازی است) |

اگر گروه پویای «محیط کارت» با بازهٔ `10.20.5.0/24` دارید، `pay-app` خودبه‌خود عضو آن است.

## مراقب باشید

> نشانی IP را دقیق وارد کنید: Syslog و پایش SNMP از روی همین نشانی به دارایی وصل می‌شوند. حذف دارایی همهٔ سوابق وابسته به آن را هم پاک می‌کند؛ برای دارایی‌ای که از کار افتاده، وضعیت را «از رده خارج» کنید.

## خطاهای رایج

| وضعیت | علت |
|---|---|
| «سقف دارایی لایسنس» | تعداد دارایی‌ها به سقف لایسنس رسیده است. |
| نشان «خارج از لایسنس» | ممیزی و مقاوم‌سازی روی این دارایی اجرا نمی‌شود. |
