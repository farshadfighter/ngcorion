# اعتبارسنجی معماری

فهرست دارایی‌ها، توپولوژی و نتایج ممیزی را با قاعده‌های معماری امن می‌سنجد و ضعف‌های ساختاری را پیدا می‌کند: دارایی بحرانی بدون افزونگی، دارایی بدون مالک یا IP، دارایی حیاتی بدون پشتیبان پیکربندی، دارایی پرریسکی که مدت‌هاست ممیزی نشده و … .

## نمونهٔ قاعده‌ها

| قاعده | شدت | دسته |
|---|---|---|
| دارایی بحرانی افزونگی ندارد | بالا | توپولوژی |
| دارایی بحرانی پشتیبان پیکربندی ندارد | بالا | تاب‌آوری |
| دارایی پرریسک فعال بدون ممیزی اخیر | بالا | انطباق |
| دارایی اتصال افزونه ندارد | متوسط | توپولوژی |
| دارایی هرگز ممیزی نشده / آخرین ممیزی ناموفق بوده | متوسط | انطباق |
| دارایی نشانی IP ندارد | متوسط | فهرست دارایی |
| دارایی مالک ندارد / سطح محرمانگی ندارد | پایین | فهرست دارایی |

## کارهای اصلی

1. «اجرای تحلیل» همهٔ قاعده‌ها را روی وضع فعلی اجرا می‌کند.
2. یافته‌های «باز» را بخوانید؛ هر کدام توصیه دارد.
3. برای هر یافته یکی از این‌ها:
    - **رفع:** مشکل را درست کنید (مثلاً مالک تعیین کنید) و دوباره تحلیل بگیرید؛ یافته ناپدید می‌شود.
    - **«پذیرش»:** خطر را آگاهانه می‌پذیرید؛ یافته به زبانهٔ «پذیرفته‌شده» می‌رود.
    - **«نادیده گرفتن»:** یافته برای شما کاربرد ندارد؛ با دلیل.

یافته‌های باز به [پیگیری اصلاح](/remediation) هم می‌روند.

## مثال

یافتهٔ «دارایی بحرانی افزونگی ندارد» برای `fw-edge`: فقط یک فایروال لبه دارید. اگر خرید فایروال دوم در برنامهٔ امسال است، تا آن موقع آن را با توضیح «پذیرش» کنید؛ اگر نه، به‌عنوان مورد پیگیری با مهلت نگه دارید.

## مراقب باشید

> قاعده‌های توپولوژی به نقشهٔ کامل نیاز دارند؛ اگر [توپولوژی](/topology) ناقص است، یافتهٔ «اتصال ندارد» زیاد می‌بینید. اول LLDP/CDP را راه بیندازید.
