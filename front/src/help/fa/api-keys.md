# کلیدهای API

سامانه‌های دیگر (SIEM، CMDB، اسکریپت‌ها) با کلید API را فرا می‌خوانند، نه با حساب یک شخص. هر کلید **حساب جداگانه‌ای** دارد که فقط دسترسی‌های همان کلید را دارد و هر کارش با نام همان حساب در دنبالهٔ ممیزی ثبت می‌شود. فقط مدیر سیستم.

## ساخت کلید

1. «کلید API تازه».
2. **نام** (مثلاً `siem-wazuh`) و توضیح: کدام سامانه از آن استفاده می‌کند و مسئولش کیست.
3. **معتبر تا:** پیش‌فرض ۹۰ روز، حداکثر ۳۶۵ روز.
4. **دسترسی:** برای هر بخش «هیچ»، «خواندن» یا «خواندن و نوشتن». فقط آنچه آن سامانه لازم دارد.
5. **«نشانی‌های مجاز (اختیاری)»:** یک نشانی یا شبکه در هر خط؛ خالی یعنی هر نشانی.
6. «ساخت کلید». توکن (`ngk_…`) **فقط همین یک بار** نمایش داده می‌شود؛ آن را مستقیم در گاوصندوق رمز سامانهٔ مقصد بگذارید و «ذخیره‌اش کردم».

## استفاده

```bash
curl -sS -H "Authorization: Bearer $TOKEN" "https://ngcorion.corp.example/api/cve/findings"
```

| پاسخ | معنی |
|---|---|
| ۴۰۱ `Invalid API key` | توکن نادرست، ناشناخته یا باطل‌شده |
| ۴۰۱ `API key has expired` | تاریخ کلید گذشته است |
| ۴۰۳ | نشانی غیرمجاز، یا کلید دسترسی این بخش را ندارد |

## چه چیزی هرگز به کلید داده نمی‌شود

مدیریت کاربران و پروفایل‌های اعتبارنامه هرگز؛ مقاوم‌سازی، پشتیبان دستگاه‌ها، تنظیمات سامانه و لاگ‌ها فقط خواندن؛ کلید هرگز چیزی را حذف نمی‌کند و هرگز مدیر سیستم نیست. پس کلید لورفته نمی‌تواند پیکربندی شبکه را تغییر دهد.

## تمدید و ابطال

- **«تمدید رمز»:** توکن تازه؛ توکن قبلی بی‌درنگ از کار می‌افتد. وقتی کسی که توکن را دیده سازمان را ترک کرد، این کار را بکنید.
- **«ابطال همیشگی»:** کلید برای همیشه از کار می‌افتد؛ حسابش برای سوابق می‌ماند.
- هشدار «کلید API به‌زودی منقضی می‌شود» (پیش‌فرض ۱۴ روز پیش از پایان) را برای مسئول آن سامانه روشن کنید.

## مراقب باشید

> هر سه ماه «آخرین استفاده» هر کلید را ببینید و کلیدهای بی‌استفاده را باطل کنید. پشت پراکسی، نشانی‌ای که NGCorion می‌بیند نشانی پراکسی است.
