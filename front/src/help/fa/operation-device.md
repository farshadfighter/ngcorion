# اجرای ممیزی

پیکربندی یک دارایی را با معیار مرجع آن (CIS، DISA STIG یا راهنمای سازنده) مقایسه می‌کند. ممیزی **فقط می‌خواند** و چیزی را روی دستگاه تغییر نمی‌دهد. فهرست این صفحه، ممیزی‌های اجراشدهٔ شماست.

## اجرای یک ممیزی

1. «ممیزی جدید».
2. **نام کار** و **دارایی**؛ نوع دستگاه از روی دارایی پیشنهاد می‌شود.
3. **اطلاعات ورود** بسته به هدف:

    | هدف | اطلاعات ورود |
    |---|---|
    | لینوکس، Apache، NGINX، Docker، Kubernetes | نام کاربری و رمز SSH، پورت، «رمز Sudo» |
    | Cisco | نام کاربری و رمز SSH و Enable |
    | FortiGate | نام کاربری و رمز SSH؛ «شناسایی VDOMها» و انتخاب یک VDOM یا «همهٔ VDOMها» |
    | ویندوز و نقش‌های آن | `Administrator` یا `DOMAIN\user`، رمز، پورت WinRM و «روش انتقال» |
    | SQL Server، MySQL، MongoDB | حساب همان پایگاه داده |
    | Sophos Firewall | حساب مدیر با دسترسی API و پورت API |
    | ESXi | root یا حسابی با نقش Administrator؛ SSH در طول ممیزی روشن باشد |

4. اگر گزینه هست (مثلاً «نقش سرور»: «کنترل‌کنندهٔ دامنه» یا «سرور عضو») آن را تعیین کنید.
5. «بعدی» و اجرا. ممیزی چند دقیقه طول می‌کشد.

## خواندن نتیجه

- «مشاهدهٔ نتیجه» امتیاز انطباق و تعداد «منطبق» و «نامنطبق» را نشان می‌دهد. هر دو روی بررسی‌های امتیازدار حساب می‌شوند، پس جمعشان ۱۰۰٪ است و درصد «منطبق» همان امتیازی است که گزارش‌ها و داشبوردها نشان می‌دهند؛ بررسی‌های «قابل اعمال نیست»، خطادار، اطلاعاتی و آن‌هایی که سیاست بنچمارک اختیاری یا مستثنا کرده جدا، با عنوان «بدون امتیاز»، شمرده می‌شوند.
- هر کنترل: بخش، شدت، نتیجه و «شواهد / اصلاح» (آنچه از دستگاه خوانده شد و توصیهٔ اصلاح).
- **«⚠ بازبینی دستی»:** بررسی تقریبی یا کنترل دستی است و باید خودتان تأییدش کنید.
- «گزارش این ممیزی، با شاهد هر کنترل»: PDF برای ممیز.
- از نتیجه مستقیم به [مقاوم‌سازی](/hardening) بروید تا کنترل‌های ناموفق را اصلاح کنید.

## مثال

`web-01` (Ubuntu): نام کاربری `ngc-audit`، پورت `22`، رمز Sudo. نتیجه: امتیاز ۶۲٪؛ یک کنترل ناموفق `5.2.10` با شاهد `PermitRootLogin: yes` و توصیهٔ `Set PermitRootLogin no in /etc/ssh/sshd_config`.

## امنیت اطلاعات ورود

- اطلاعات ورود فقط در طول همین اجرا به کار می‌رود و ذخیره نمی‌شود.
- در اولین اتصال، کلید SSH (یا گواهی HTTPS سوفوس) دستگاه پین می‌شود. اگر بعداً عوض شود، اتصال **پیش از فرستادن هر رمزی** رد می‌شود؛ اتصال را تکرار نکنید و به مدیر سیستم خبر دهید.
- برای ممیزی منظم، [ممیزی گروهی](/audit/group-runs) با پروفایل اعتبارنامه را ترجیح دهید.

## خطاهای رایج

| وضعیت | علت و راه |
|---|---|
| ممیزی ناموفق بود | نشانی، پورت، نام کاربری، رمز یا فایروال میان راه |
| بسیاری از کنترل‌ها خطا دارند | رمز Sudo داده نشده یا حساب دسترسی خواندن فایل‌ها را ندارد |
| WinRM وصل نمی‌شود | WinRM روی سرور روشن نیست یا روش انتقال اشتباه است |
| کلید میزبان تغییر کرده است | دستگاه دوباره نصب شده یا جعل شده؛ به مدیر سیستم خبر دهید |

## مراقب باشید

> حذف یک ممیزی یا «پاک کردن تاریخچه» برگشت‌پذیر نیست، ولی رکورد دنبالهٔ ممیزی («چه کسی چه زمانی ممیزی کرد») پاک نمی‌شود. هر کاربر غیر از مدیر سیستم فقط ممیزی‌های خودش را می‌بیند.
