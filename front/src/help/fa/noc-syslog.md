# Syslog

پیام‌هایی که خود دارایی‌ها دربارهٔ خودشان می‌فرستند: خطاها، ورودهای ناموفق، تغییر پیکربندی، قطع شدن رابط‌ها. پیام فقط وقتی نگه داشته می‌شود که نشانی فرستنده، نشانی IP یک دارایی در فهرست باشد.

## راه‌اندازی

1. **مدیر سیستم:** زبانهٔ «تنظیمات» ← «دریافت Syslog از دارایی‌ها» را روشن کنید. در فایروال، پورت 514 را فقط از شبکه‌های دستگاه‌ها به NGCorion باز کنید.
2. **روی دستگاه‌ها** (همین نمونه‌ها با نشانی واقعی NGCorion در زبانهٔ «تنظیمات» آمده است):

    Cisco IOS:

    ```
    logging host 10.20.9.10 transport udp port 514
    logging trap informational
    service timestamps log datetime msec
    ```

    FortiGate:

    ```
    config log syslogd setting
        set status enable
        set server "10.20.9.10"
        set port 514
    end
    ```

    لینوکس (rsyslog؛ `@@` یعنی TCP و `@` یعنی UDP):

    ```
    *.* @@10.20.9.10:514
    ```

3. زبانهٔ «منابع»: هر دستگاه کی آخرین پیام را فرستاده است.

## جستجو در پیام‌ها

صافی دارایی، شدت (مثلاً «خطا و شدیدتر»)، بازهٔ زمانی و جستجو در متن، نام برنامه یا میزبان. «زنده» هر ۵ ثانیه تازه می‌کند و «خروجی CSV» همان پیام‌های صافی‌شده را می‌دهد (حداکثر ۵۰٬۰۰۰).

**مثال:** ورودهای ناموفق SSH در ۲۴ ساعت گذشته: بازهٔ «۲۴ ساعت گذشته» و جستجوی `Failed password`.

## تغییر پیکربندی گزارش‌شده

پیام تغییر پیکربندی Cisco (`%SYS-5-CONFIG_I`)، NX-OS و FortiGate با نام کاربر و نشانی او ثبت می‌شود و حدود یک دقیقه بعد [پشتیبان‌گیری فوری](/backup/schedules) را راه می‌اندازد (اگر «پشتیبان‌گیری از دستگاه وقتی تغییر پیکربندی را گزارش می‌دهد» روشن باشد).

## هشدارها

«پیام Syslog شدید» (پیش‌فرض بحرانی و شدیدتر)، «دارایی دیگر Syslog نمی‌فرستد» (پس از ۲۴ ساعت) و، به‌طور پیش‌فرض خاموش، «Syslog از نشانی‌ای بیرون از فهرست دارایی‌ها».

## خطاهای رایج

| وضعیت | علت |
|---|---|
| پیام یک دستگاه نمی‌رسد | نشانی فرستنده با IP دارایی یکی نیست؛ در زبانهٔ منابع، زیر «نشانی‌های بیرون از فهرست دارایی‌ها»، با «نسبت دادن به یک دارایی…» آن را یکی از نشانی‌های دارایی کنید (یا در ویرایش «شبکه و سیستم» دارایی، «نشانی‌های دیگر») |
| «دریافت Syslog روشن است اما پیامی دریافت نمی‌شود» | فایروال پورت 514 یا درگاه گرفته‌شده؛ با مدیر سیستم |
| پیام‌های کم‌اهمیت ذخیره نمی‌شوند | سطح «نگه‌داشتن پیام‌ها در سطح» در تنظیمات بالاتر است |

## مراقب باشید

> Syslog احراز هویت ندارد و هر کسی در شبکه می‌تواند پیامی با نشانی جعلی بفرستد؛ پیام‌ها هرگز اجرا نمی‌شوند و تنها اثرشان پشتیبان‌گیری فقط‌خواندنی (حداکثر هر ۵ دقیقه یک بار) است. TCP را بر UDP ترجیح دهید.
