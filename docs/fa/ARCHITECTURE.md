| مورد | مقدار |

این سند اجزای NGCorion، مرزهای اعتماد و جریان داده‌ها را شرح می‌دهد و نشان می‌دهد سازوکارهای امنیتی
(TSF) چگونه **به‌طور امن راه‌اندازی می‌شوند**، **از خود محافظت می‌کنند**، **دامنه‌ها را جدا نگه
می‌دارند** و **قابل دور زدن نیستند**. هر ادعا به محل آن در کد ارجاع دارد.

---

## ۱. نمای کلی

NGCorion یک برنامهٔ وب چندکاربره است که دارایی‌های فناوری اطلاعات سازمان را فهرست، ممیزی و
مقاوم‌سازی می‌کند و آسیب‌پذیری‌ها، ریسک، اصلاحات، گزارش‌ها و هشدارها را مدیریت می‌کند. به دو شکل
تحویل می‌شود: ماشین مجازی آماده (OVA/VHDX/qcow2) و استقرار Docker Compose. در هر دو شکل اجزای
زمان اجرا یکسان‌اند.

```
                       مرز TOE
 ┌──────────────────────────────────────────────────────────────────────────┐
 │  ماشین مجازی (Ubuntu 24.04، بدون پوسته؛ کنسول منومحور)                   │
 │                                                                          │
 │   ┌─────────┐ HTTPS  ┌──────────────────────────────────────────────┐    │
 │   │ Traefik │──────►│ backend (FastAPI + uvicorn، UID 10001)        │    │
 │   │  TLS    │ HTTP   │  ├─ API: /auth/*، /api/*                      │    │
 │   └────▲────┘ داخلی  │  ├─ رابط وب ساخته‌شده (React) از همین مبدأ     │    │
 │        │            │  └─ کارهای پس‌زمینه (هر کدام در یک worker)     │    │
 │        │            └───────┬──────────────────────────────────────┘    │
 │        │                    │ شبکهٔ داخلی Docker                         │
 │        │              ┌─────▼──────┐                                     │
 │        │              │ PostgreSQL │                                     │
 │        │              └────────────┘                                     │
 └────────┼──────────────────────┬──────────────────────┬───────────────────┘
          │ 443                  │ SSH/WinRM/SQL/API    │ HTTPS
   مرورگر کاربران          دارایی‌های ممیزی‌شونده     lic.ngcorion.com، NVD/OSV،
                                                       SMTP، پیامک، Syslog، وب‌هوک،
                                                       SFTP/SMB (پشتیبان)
```

استقرار فقط همین سه کانتینر را دارد (Traefik، backend، PostgreSQL)؛ هیچ سرویس استفاده‌نشده‌ای اجرا
نمی‌شود.

## ۲. مرزهای اعتماد و جریان داده‌ها

| # | جریان | مرز | حفاظت |
|---|---|---|---|
| 1 | مرورگر ↔ Traefik | شبکهٔ سازمان → TOE | TLS 1.2/1.3، HSTS؛ پورت 80 فقط هدایت به HTTPS. |
| 2 | Traefik ↔ backend | درون TOE (شبکهٔ داخلی Docker) | backend منتشر نمی‌شود؛ فقط از Traefik در دسترس است. |
| 3 | backend ↔ PostgreSQL | درون TOE | شبکهٔ داخلی، رمز اختصاصی هر نصب (`POSTGRES_PASSWORD`). |
| 4 | backend → دارایی‌ها | TOE → محیط | SSH با پین کلید میزبان؛ HTTPS (Sophos) با پین گواهی؛ اطلاعات ورود فقط در حافظه و در طول اجرا (بند ۴.۴). |
| 5 | backend → `lic.ngcorion.com` | TOE → محیط | HTTPS با بررسی گواهی در برابر CAهای عمومی؛ پاسخ با Ed25519 امضا و با nonce درخواست گره خورده است. |
| 6 | backend → فیدهای CVE/OSV | TOE → محیط | HTTPS؛ بسته‌های آفلاین با امضای Ed25519 و فهرست کلیدهای مورد اعتماد. |
| 7 | backend → SMTP، پیامک، Syslog، وب‌هوک | TOE → محیط | نشانی درگاه پیامک و وب‌هوک در برابر SSRF بررسی می‌شود؛ وب‌هوک با HMAC-SHA256 و برچسب زمان امضا می‌شود. |
| 8 | backend → مقصد پشتیبان | TOE → محیط | فایل پشتیبان پیش از خروج رمزنگاری شده است (AES-256-GCM)؛ کلید میزبان SFTP پین می‌شود. |
| 9 | کنسول هایپروایزر → ماشین | محیط → TOE | منوی محدود، بدون پوسته (فرض A.PLATFORM). |
| 10 | دارایی‌ها → backend (Syslog، ‏514/UDP و TCP) | محیط → TOE | به‌طور پیش‌فرض خاموش؛ فقط نشانی‌های دارایی‌های ثبت‌شده پذیرفته می‌شوند؛ محدودیت نرخ، اندازهٔ پیام و تعداد اتصال؛ ورودی فقط تجزیه و ذخیره می‌شود و هرگز اجرا نمی‌شود؛ پیام تغییر پیکربندی فقط یک پشتیبان‌گیری فقط‌خواندنی از همان دارایی (با پروفایل اعتبارنامهٔ زمان‌بندی موجود، حداکثر یک بار در ۵ دقیقه) را راه می‌اندازد. احراز هویت ندارد (محدودیت ذاتی Syslog)؛ دسترسی را فایروال محیط محدود می‌کند. |

## ۳. مسیر یک درخواست

ترتیب میان‌افزارها از بیرونی‌ترین (`app/main.py`):

1. **SecurityHeadersMiddleware** — CSP، `X-Frame-Options: DENY`، `nosniff`، HSTS روی HTTPS، `no-store`
   برای API. بیرونی‌ترین است تا حتی پاسخ‌های کوتاه‌شده هم سرآیندها را داشته باشند.
2. **CORSMiddleware** — فقط فهرست صریح؛ `*` در راه‌اندازی رد می‌شود. در استقرار عادی خالی است چون
   رابط وب و API هم‌مبدأند.
3. **LicenseMiddleware** — هر `/api/*` را تا وجود لایسنس معتبر رد می‌کند؛ جز ورود، `/health`، وضعیت و
   فعال‌سازی لایسنس.
4. **MaintenanceMiddleware** — هنگام بازیابی پشتیبان سامانه درخواست‌ها را برمی‌گرداند.

سپس وابستگی‌های مسیر (`app/core/dependencies.py`):

* `get_current_user`: امضا و انقضای JWT؛ رد توکن باطل‌شده (`revoked_tokens`)؛ رد توکنی که اثر رمز
  (`pwv`) آن با رمز فعلی نمی‌خواند؛ بارگذاری کاربر و نقش از پایگاه داده (نه از توکن)؛ رد حساب
  غیرفعال؛ اعمال بی‌کاری نشست (`touch_session`)؛ محدود کردن حساب نیازمند تغییر رمز به مسیرهای تغییر
  رمز و نشست.
* `require_permission(module, read|write|delete)`، `require_admin`، `require_admin_or_manager`.
* مالکیت: `assert_session_access`، `owner_scope`، `require_own_session/result/action`.
* سقف لایسنس: `require_licensed_asset` پیش از هر اتصال ممیزی/مقاوم‌سازی، و نگهبان `before_flush` برای
  افزودن دارایی.

## ۴. معماری امنیتی (ADV_ARC.1)

### ۴.۱ راه‌اندازی امن

| مرحله | آنچه تضمین می‌شود | محل |
|---|---|---|
| ساخت ایمیج | کد و رابط وب ساخته‌شده درون ایمیج، متعلق به root و فقط‌خواندنی برای کاربر برنامه؛ ماژول‌های منطق (لایسنس، مجوزها، کارکردها) به ماژول بومی کامپایل می‌شوند؛ CI بررسی می‌کند که هیچ `.env` یا رازی در ایمیج نباشد. | `Dockerfile.ngcorion`، `scripts/compile_app.py`، `.github/workflows/ci.yml` |
| اولین روشن شدن ماشین | machine-id، `SECRET_KEY` (۲۵۶ بیت)، رمز پایگاه داده و گواهی وب برای همان ماشین ساخته می‌شوند؛ ایمیج هیچ رازی ندارد؛ رمز `admin` موقت است. | `appliance/ngcorion_appliance/render.py`، `wizard.py` |
| شروع کانتینر | `entrypoint.sh` کارهای نیازمند root را انجام می‌دهد و سپس با `setpriv` به UID/GID 10001 تغییر می‌کند؛ مهاجرت‌ها (`alembic upgrade head`) پیش از سرویس‌دهی اجرا می‌شوند. | `entrypoint.sh` |
| بارگذاری برنامه | `SECRET_KEY` اگر مقدار منتشرشده یا کوتاه‌تر از ۳۲ نویسه باشد، برنامه **شروع نمی‌شود**؛ CORS ناامن (`*`) شروع را متوقف می‌کند. | `app/core/config.py` (`require_secure_secret_key`، `resolve_cors_origins`) |
| وضعیت لایسنس | وضعیت ذخیره‌شده فقط پس از تأیید دوبارهٔ امضای آن پذیرفته می‌شود؛ تا لایسنس معتبر نباشد، API بسته است (حالت پیش‌فرض: رد). | `app/core/license_state.py`، `license_middleware.py` |
| کارهای پس‌زمینه | هر کار فقط در یک worker با قفل مشورتی PostgreSQL اجرا می‌شود. | `app/core/singleton.py` |

### ۴.۲ حفاظت از خود (Self-protection)

* **کد غیرقابل‌تغییر در زمان اجرا:** کاربر برنامه (UID 10001) نمی‌تواند کد، کتابخانه‌ها یا رابط وب
  را تغییر دهد؛ فقط حجم‌های داده (لایسنس، پشتیبان‌ها، کلیدهای پین‌شده) قابل نوشتن‌اند.
* **ماشین مجازی بسته:** بدون پوسته؛ SSH پیش‌فرض خاموش و پس از روشن شدن فقط منوی کنسول (ForceCommand، بدون
  انتقال فایل و تونل، قفل پس از رمز نادرست)؛ root قفل، بدون getty، GRUB قفل، Secure Boot؛ دیسک سیستم با
  بزرگ شدن دیسک مجازی خودکار بزرگ می‌شود.
  کنسول فقط منو است و پوسته نمی‌دهد (`appliance/ngcorion_appliance/console.py`).
* **رازها:** رمز کاربران با bcrypt؛ رازهای ذخیره‌شده (اطلاعات ورود کارهای زمان‌بندی‌شده، SNMP،
  SMTP، پیامک، کلید NVD، مقصد پشتیبان، کلید امضای وب‌هوک) با Fernet و کلیدی که برای **هر کاربرد**
  جداگانه با HKDF از `SECRET_KEY` مشتق می‌شود؛ هیچ رازی در پاسخ API بازگردانده نمی‌شود (فقط «تنظیم
  شده»).
* **دنبالهٔ ممیزی تغییرناپذیر:** تریگر `audit_logs_no_change` هر UPDATE/DELETE را رد می‌کند؛ تنها
  موتور پشتیبان/بازیابی با یک GUC جلسه‌ای (`ngcorion.audit_maintenance`) مجاز است کل پایگاه داده را
  جایگزین کند. سوابق ورود از رابط پاک نمی‌شوند.
* **سقف و یکپارچگی لایسنس:** کلیدهای عمومی امضا و نشانی سرور لایسنس در کد (نه پیکربندی)‌اند؛ پاسخ
  امضانشده، پاسخی برای ماشین یا لایسنس دیگر، یا عقب کشیدن ساعت پذیرفته نمی‌شود.
* **ورودی:** همهٔ بدنه‌ها با Pydantic اعتبارسنجی می‌شوند؛ پارامترهای مقاوم‌سازی پیش از رسیدن به
  دستور، از نظر نوع، بازه، فهرست مجاز و نویسه‌های خطرناک پوسته بررسی می‌شوند؛ خروجی‌های
  Excel/CSV در برابر تزریق فرمول خنثی می‌شوند؛ پرس‌وجوها پارامتری‌اند (ORM).
* **محدودیت منابع:** محدودیت تلاش ورود و درخواست بازیابی رمز، سقف اندازهٔ بارگذاری‌ها (لوگو، بستهٔ
  CVE، فایل لایسنس).

### ۴.۳ جداسازی دامنه

* **بین کاربران:** همهٔ کاربران از یک نمونهٔ برنامه استفاده می‌کنند؛ جداسازی منطقی است: هر درخواست
  هویت خود را دارد، داده‌ها با نقش و مجوز ماژول فیلتر می‌شوند و هر کاربر غیرمدیر فقط نشست‌های ممیزی
  و مقاوم‌سازی خودش را می‌بیند (درخواست نشست دیگران پاسخ ۴۰۴ می‌گیرد). هیچ‌کس نمی‌تواند نقش یا
  مجوز خودش را تغییر دهد یا مجوزی فراتر از مجوزهای خودش اعطا کند.
* **بین TSF و محیط:** کانتینرها فضای نام و فایل‌سیستم جدا دارند؛ PostgreSQL فقط روی شبکهٔ
  داخلی است؛ پورت مدیریتی Traefik فقط روی loopback است و API آن خاموش است.
* **بین نصب‌ها:** هر نصب machine-id، رازها، گواهی و اثر انگشت لایسنس خود را دارد؛ پشتیبانِ یک نصب
  هنگام بازیابی روی نصب دیگر با کلید نصب مقصد دوباره رمزنگاری می‌شود.
* **بین دارایی‌ها:** کلید میزبان هر دستگاه جدا پین می‌شود؛ اطلاعات ورود یک اجرا به اجرای دیگر
  نمی‌رسد.

### ۴.۴ عدم‌امکان دور زدن

* **یک نقطهٔ ورود:** همهٔ درخواست‌ها از Traefik و سپس زنجیرهٔ میان‌افزار می‌گذرند؛ backend منتشر
  نمی‌شود.
* **احراز هویت در هر مسیر:** هر مسیر `/api/*` و `/auth/*` (جز ورود، بنر ورود، فراموشی و بازنشانی رمز)
  به `get_current_user` وابسته است؛ نقش و مجوز در هر درخواست از پایگاه داده خوانده می‌شود، پس تغییر
  مجوز یا غیرفعال شدن حساب بی‌درنگ اثر می‌کند. مسیرهای عمومی: `/health` (فقط وضعیت و نسخه)،
  `GET /api/license/status`، و فعال‌سازی لایسنس فقط تا وقتی لایسنسی معتبر نیست.
* **مستندات API:** `/openapi.json` فقط برای کاربر واردشده؛ `/docs` صفحهٔ ایستایی است که بدون توکن
  چیزی نشان نمی‌دهد.
* **اطلاعات ورود دستگاه‌ها:** در درخواست می‌آیند، فقط در حافظهٔ همان اجرا استفاده می‌شوند و در
  پایگاه داده، لاگ یا پاسخ ذخیره نمی‌شوند (استثنا: کارهای زمان‌بندی‌شده، رمزنگاری‌شده). شاهدهای
  ممیزی پیش از ذخیره از رازها پاک می‌شوند (`redact`).
* **کلید میزبان:** حالت «خاموش» برای بررسی کلید وجود ندارد؛ کلید ناشناخته در حالت `strict` و کلید
  متفاوت در هر حالت، **پیش از ارسال رمز**، اتصال را متوقف می‌کند. حذف پین فقط برای مدیر سیستم و با
  ثبت در دنبالهٔ ممیزی ممکن است.
* **مقاوم‌سازی:** فقط از مسیر پیش‌نمایش/پارامتر/اجرا؛ موفقیت فقط با راستی‌آزمایی (`PASS`) اعلام
  می‌شود.

## ۵. رمزنگاری

| کاربرد | سازوکار | محل |
|---|---|---|
| کانال کاربر | TLS 1.2/1.3، ECDHE + AES-GCM/ChaCha20-Poly1305 | `traefik/dynamic/tls.yml` |
| رمز کاربران | bcrypt (passlib) | `app/core/security.py` |
| توکن نشست | JWT HS256 با `SECRET_KEY` (≥ ۳۲ نویسه)؛ ادعاهای `exp`، `iat`، `jti` (باطل‌سازی)، `pwv` (اثر رمز) | `app/core/security.py` |
| کد بازیابی رمز | فقط SHA-256 آن ذخیره می‌شود؛ ۱۰ دقیقه، ۵ تلاش | `app/modules/auth/` |
| رازهای ذخیره‌شده | Fernet (AES-128-CBC + HMAC-SHA256)، کلید هر کاربرد با HKDF-SHA256 از `SECRET_KEY` | `app/core/credential_crypto.py` |
| پاسخ‌ها و فایل‌های لایسنس | تأیید امضای Ed25519 با کلیدهای عمومی درون کد | `app/core/license_keys.py`، `license_token.py` |
| بسته‌های CVE آفلاین | امضای Ed25519 و فهرست کلیدهای مورد اعتماد | `app/modules/cve/` |
| پشتیبان سامانه | AES-256-GCM در قطعه‌های احرازشده، کلید از رمز پشتیبان با scrypt (N=2^15, r=8, p=1) | `app/modules/sysbackup/container.py` |
| وب‌هوک | HMAC-SHA256 روی «برچسب زمان.بدنه» | `app/modules/alerts/channels.py` |
| اصالت فایل گزارش | SHA-256 در بایگانی | `app/modules/reports/service.py` |
| اتصال SSH به دارایی‌ها | paramiko/netmiko؛ الگوریتم‌های SHA-2 مقدم؛ پین کلید میزبان (اثر SHA-256) | `app/core/ssh_host_keys.py`؛ استثنای مستند در `SECURITY.md` |

مدیریت کلید: `SECRET_KEY` و رمز پایگاه داده در `.env` نصب (دسترسی محدود)؛ رمز پشتیبان نزد سازمان؛
کلید خصوصی امضای لایسنس هرگز در NGCorion نیست (فقط روی سرور لایسنس).

## ۶. داده‌ها

| داده | محل | حفاظت |
|---|---|---|
| کاربران، نقش‌ها، مجوزها | PostgreSQL | رمزها bcrypt |
| نشست‌ها و توکن‌های باطل‌شده | `user_sessions`، `revoked_tokens` | — |
| دنبالهٔ ممیزی | `audit_logs`، `login_logs` | تریگر ضدتغییر |
| دارایی‌ها، نتایج ممیزی، شاهدها، یافته‌ها، گزارش‌ها | PostgreSQL، بایگانی گزارش | کنترل دسترسی و مالکیت؛ پاک‌سازی رازها از شاهدها |
| پیکربندی پشتیبان دستگاه‌ها | `device_backups` | کنترل دسترسی (بازیابی فقط مدیر/مدیر سیستم) |
| رازهای ذخیره‌شده | ستون‌های `*_encrypted` | Fernet + HKDF |
| کلیدهای پین‌شده | `/etc/ngcorion/known_hosts`، `tls_pins.json` | حالت 600؛ نوشتن اتمیک با قفل فایل |
| لایسنس | `/var/lib/ngcorion/license` | رمزنگاری‌شده؛ وضعیت امضاشده |
| پشتیبان‌های سامانه | `/var/lib/ngcorion/backups` و مقصدها | AES-256-GCM |

طرح پایگاه داده فقط با مهاجرت‌های Alembic تغییر می‌کند و CI بررسی می‌کند که فقط یک head وجود دارد.

## ۷. کارهای پس‌زمینه

| کار | کاربرد |
|---|---|

| cve-auto-update | به‌روزرسانی روزانهٔ CVE/KEV/EPSS و اطلاعیه‌ها |
| alert-engine | ارزیابی قوانین هشدار و ارسال اعلان |
| remediation-sync | هم‌گام‌سازی موارد اصلاح با یافته‌ها |
| audit-policy | امتیازدهی ممیزی‌ها زیر سیاست بنچمارک‌ها و پایان قانون‌های منقضی |
| report-worker | ساخت گزارش‌های درخواستی و زمان‌بندی‌شده |
| system-backup | پشتیبان خودکار و آزمون بازیابی |

worker دیگری آن را می‌گیرد. توقف هر کار هشدار «توقف کار پس‌زمینه» می‌دهد.

## ۸. ارتباط با سرور لایسنس

1. NGCorion اثر انگشت ماشین را می‌سازد (UUID سخت‌افزار/ماشین مجازی و machine-id).
2. درخواست فعال‌سازی/اعتبارسنجی/heartbeat همراه با یک nonce تصادفی فقط با HTTPS به
   `https://lic.ngcorion.com` فرستاده می‌شود.
3. پاسخ فقط وقتی پذیرفته می‌شود که توکن آن با یکی از کلیدهای عمومی Ed25519 درون کد امضا شده باشد،
   دربارهٔ همین کلید لایسنس و همین ماشین باشد و nonce همین درخواست را برگرداند. وضعیت لایسنس فقط از
   ادعاهای امضاشده ساخته می‌شود.
4. وضعیت امضاشده روی دیسک نگه داشته و در شروع بعدی دوباره تأیید می‌شود. بدون پاسخ: ۴۸ ساعت طرح
   لایسنس، سپس ۳۰ روز پایلوت (۵ دارایی)، سپس قفل؛ عقب کشیدن ساعت وضعیت را نامعتبر می‌کند.
5. لایسنس آفلاین: فایل امضاشده برای همین ماشین، حداکثر یک سال؛ بدون هیچ ارتباط شبکه‌ای.

**محدودیت:** کسی که بتواند کد NGCorion را روی سرور تغییر دهد می‌تواند این بررسی‌ها را حذف کند؛ امضا
از دور زدن از راه پیکربندی (سرور جعلی، حافظهٔ دستکاری‌شده) جلوگیری می‌کند، نه از تغییر کد. حفاظت
در برابر تغییر کد بر عهدهٔ ایمیج فقط‌خواندنی، ماشین مجازی بسته و فرض A.PLATFORM است.

## ۹. محدودیت‌ها و موارد خارج از ادعا

* دیسک ماشین مجازی رمزنگاری نمی‌شود و سیستم فایل ریشه فقط‌خواندنی نیست؛ حفاظت دیسک بر عهدهٔ محیط
  است (A.PLATFORM).
* paramiko برای سازگاری با تجهیزات قدیمی الگوریتم‌های SHA-1 را به‌عنوان آخرین گزینه می‌پذیرد؛
  پین کلید میزبان این را جبران می‌کند (`SECURITY.md`).
* به‌روزرسانی ماشین مجازی با استقرار ایمیج جدید و بازیابی پشتیبان انجام می‌شود؛ سازوکار
  به‌روزرسانی امضاشدهٔ درجا وجود ندارد.
