# هدف امنیتی (Security Target) — NGCorion

> **وضعیت:** پیش‌نویس برای ارائه به آزمایشگاه ارزیابی امنیتی مورد تأیید مرکز افتا.
> ساختار طبق ISO/IEC 15408 (معیار مشترک، CC 3.1 R5) بخش ۱ پیوست A است.
> نسخهٔ نهایی را آزمایشگاه بر اساس دامنه و سطح ارزیابی توافق‌شده بازبینی می‌کند.
> هر ادعا در این سند به کد مشخصی ارجاع دارد تا ارزیاب بتواند آن را بررسی کند.

| مورد | مقدار |
|---|---|
| عنوان سند | هدف امنیتی NGCorion |
| نسخهٔ سند | 0.9 (پیش‌نویس) |
| محصول (TOE) | NGCorion — سامانهٔ ممیزی و مقاوم‌سازی امنیتی زیرساخت |
| نسخهٔ محصول | 2.1.0 (شناسهٔ دقیق: تگ گیت `v2.1.0` و `VERSION` در `app/core/config.py`) |

| معیار | ISO/IEC 15408:2022 / CC 3.1 R5، روش ارزیابی ISO/IEC 18045 |

## ۱. معرفی محصول (TOE Overview)

### ۱.۱ نوع و کاربرد

NGCorion یک برنامهٔ تحت وب برای سازمان‌هاست که:

* دارایی‌های فناوری اطلاعات (سرور، تجهیزات شبکه، پایگاه داده، سرویس‌ها) را فهرست و کشف می‌کند؛
* پیکربندی آن‌ها را با معیارهای CIS / DISA STIG / راهنمای سازندگان **ممیزی** می‌کند؛
* با تأیید کاربر، تنظیمات امن را **اعمال** (مقاوم‌سازی) و در صورت نیاز بازگردانی می‌کند؛
* آسیب‌پذیری‌ها (CVE و اطلاعیه‌های توزیع‌ها)، ریسک، اصلاحات و گزارش‌ها را مدیریت می‌کند.

### ۱.۲ شکل تحویل

* **ماشین مجازی آماده (Appliance):** فایل OVA (VMware)، VHDX (Hyper-V)، qcow2 (KVM)، مبتنی بر Ubuntu 24.04،
  بدون SSH و بدون پوستهٔ ورود؛ پیکربندی اولیه فقط از کنسول (`appliance/`).
* **نصب روی Docker** با `docker-compose.yml` (Traefik، backend، PostgreSQL).

### ۱.۳ مرز فیزیکی و منطقی TOE

```
مرورگر کاربر ──HTTPS──► Traefik (TLS) ──► NGCorion backend (FastAPI) ──► PostgreSQL
                                              │
                                              ├── SSH/WinRM/API ──► دارایی‌های ممیزی‌شونده
                                              └── HTTPS ──► سرور لایسنس (lic.ngcorion.com)
```

**داخل TOE:** کد backend (`app/`)، رابط وب (`front/`)، کنفیگ Traefik و ماشین مجازی (`appliance/`).
**محیط عملیاتی (خارج از TOE):** هایپروایزر، شبکه، مرورگر کاربر، سرور زمان (NTP)، سرور ایمیل (بازیابی رمز)،
دارایی‌های ممیزی‌شونده، سرور لایسنس (هدف امنیتی جداگانه دارد).

### ۱.۴ کارکردهای امنیتی (TSF)

| کارکرد | خلاصه |
|---|---|
| شناسایی و احراز هویت | حساب شخصی برای هر کاربر، سیاست رمز، محدودیت تلاش ناموفق، تغییر اجباری رمز موقت |
| مدیریت نشست | توکن با شناسهٔ یکتا، خروج سمت سرور، پایان نشست پس از بیکاری، حداکثر عمر توکن |
| کنترل دسترسی | نقش‌ها (admin، manager، user، guest) و مجوزهای خواندن/نوشتن/حذف در ۲۰ ماژول |
| ممیزی | ثبت رویدادهای امنیتی با هویت، زمان، نشانی و نتیجه؛ دنبالهٔ ممیزی غیرقابل‌تغییر |
| حفاظت از دادهٔ حساس | رمزنگاری اعتبارنامه‌های ذخیره‌شده، ذخیره نکردن اعتبارنامهٔ اجراهای دستی، تثبیت کلید میزبان SSH |
| کانال امن | HTTPS (TLS 1.2+) با سرآیندهای امنیتی؛ TLS به سرور لایسنس با بررسی گواهی |
| یکپارچگی لایسنس | پاسخ‌های امضاشده با Ed25519 و کلید عمومی درون کد |

## ۲. ادعای انطباق

* ISO/IEC 15408-2 (الزامات کارکردی): انطباق — فقط مؤلفه‌های استاندارد.
* ISO/IEC 15408-3 (الزامات تضمین): انطباق — بستهٔ EAL2 به‌علاوهٔ ALC_FLR.1.
* ادعای انطباق با Protection Profile: ندارد.

## ۳. تعریف مسئلهٔ امنیتی

### ۳.۱ دارایی‌های حفاظت‌شده

* اعتبارنامه‌های دسترسی به دارایی‌ها (رمز SSH/WinRM/پایگاه داده)؛
* نتایج ممیزی، یافته‌های آسیب‌پذیری و گزارش‌ها (اطلاعات حساس از ضعف‌های سازمان)؛
* تنظیمات اعمال‌شده روی دارایی‌ها (مقاوم‌سازی) و نسخه‌های پشتیبان پیکربندی؛
* حساب‌های کاربری و دنبالهٔ ممیزی.

### ۳.۲ تهدیدها

| شناسه | تهدید |
|---|---|
| T.UNAUTH_ACCESS | مهاجم بدون حساب معتبر به کارکردها یا داده‌ها دسترسی پیدا کند (حدس رمز، سرقت توکن، نشست رهاشده). |
| T.PRIVILEGE | کاربر مجاز کاری فراتر از نقش و مجوزش انجام دهد. |
| T.CRED_DISCLOSURE | اعتبارنامهٔ دارایی‌ها از پایگاه داده، لاگ یا پاسخ API افشا شود. |
| T.EAVESDROP | داده یا اعتبارنامه در شبکه شنود یا دستکاری شود. |
| T.UNDETECTED | اقدام مخرب یا اشتباه بدون ردپا بماند یا ردپای آن پاک شود. |
| T.ROGUE_DEVICE | مهاجم خود را جای دارایی هدف جا بزند تا اعتبارنامه را بگیرد (MITM روی SSH). |
| T.LICENSE_FORGERY | سرور لایسنس جعلی یا پاسخ دستکاری‌شده محدودیت‌های لایسنس را دور بزند. |
| T.WEB_ATTACK | حملات وب (تزریق، XSS، CSRF، SSRF، دستکاری پارامتر) طبق OWASP WSTG. |

### ۳.۳ سیاست‌های سازمانی

| شناسه | سیاست |
|---|---|
| P.ACCOUNTABILITY | هر اقدام امنیتی به یک کاربر مشخص نسبت داده شود. |
| P.BANNER | پیش از ورود، اطلاعیهٔ استفادهٔ مجاز نمایش داده شود. |
| P.CHANGE_APPROVAL | تغییر پیکربندی دارایی‌ها فقط با تأیید صریح کاربر مجاز و همراه با پشتیبان انجام شود. |

### ۳.۴ فرض‌ها

| شناسه | فرض |
|---|---|
| A.ADMIN | مدیران سامانه مورد اعتماد و آموزش‌دیده‌اند و از راهنمای استفاده پیروی می‌کنند. |
| A.PLATFORM | هایپروایزر و شبکهٔ میزبان تحت کنترل سازمان و ایمن است؛ دسترسی کنسول ماشین مجازی محدود است. |
| A.TIME | منبع زمان قابل‌اعتماد (NTP) در دسترس است. |
| A.NETWORK | دسترسی به رابط مدیریتی فقط از شبکه‌های مجاز است. |
| A.BROWSER | مرورگر کاربران به‌روز است. |

سرآیندهای CSP/X-Frame-Options/nosniff.

## ۸. منطق پوشش (خلاصه)

* هر تهدید بند ۳.۲ حداقل با یک هدف بند ۴.۱ پوشش داده شده و هر هدف حداقل با یک SFR بند ۵.
* وابستگی‌های SFR: FAU_GEN.1←FPT_STM.1 (محیط، A.TIME)؛ FIA_AFL.1←FIA_UAU.1 (پوشش با FIA_UAU.2)؛
  FMT_MTD.1←FMT_SMR.1 و FMT_SMF.1؛ FCS_COP.1←مدیریت کلید (کلید Fernet و SECRET_KEY در تنظیمات محیط؛
  کلید لایسنس درون کد).
